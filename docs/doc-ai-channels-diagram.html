Key Differences: Outbound Notification vs. Extension (Callback)
🔔 Outbound Channel — Notification
A one-way push. When a document reaches a defined status, Document AI sends a notification to the target system — fire and forget.
  • 1
    Document reaches a defined status (e.g. extraction complete)
  • 2
    Outbound channel is triggered automatically
  • 3
    HTTP POST sent to target URL (with optional extraction results in payload)
  • 4
    Document AI does not wait for a response — processing is complete
  • 5
    Target system handles the notification independently
Fire & forget — no response expected
🔁 Outbound Channel — Extension (Callback)
A two-way intercept. Document AI calls an external system mid-processing, waits for it to act and respond, then continues the workflow based on the result.
  • 1
    Workflow reaches an extension node during processing
  • 2
    Document AI sends a callback to the configured outbound channel (target system)
  • 3
    Target system performs its action (e.g. validation, enrichment, approval)
  • 4
    Target system responds to Document AI with result
  • 5
    Document AI resumes processing based on the response
Bidirectional — Document AI waits for response
SAP BTP Destinations  ·  Both inbound and outbound channels use SAP BTP Destinations for connectivity. Destination type is always HTTP. Proxy can be Internet (external REST/SOAP) or OnPremise (via Cloud Connector). Authentication options: NoAuth, Basic, Client Certificate, OAuth2 Client Credentials, OAuth2 Technical User Propagation. Destination names are auto-prefixed with DOC_AI_.
