SAP Document AI — Extension Pattern
Callback Flow with AI Core Enrichment via Integration Suite
Document AI triggers an Extension callback → SAP Integration Suite iFlow handles all API calls to SAP AI Core → AI Core runs RPT-1 and Perplexity internally → enriched result returned to Document AI.

Phase 1 — Document Intake & Extraction
1 Invoice received Via Inbound Channel (e.g. Outlook). Stored in Workspace.
2 Workflow runs Email Split → Classification → Extraction. ML / GenAI extracts fields.
3 Status → After Prediction Extraction complete. Extension node reached. Callback triggered.
Phase 2 — Extension Callback (Doc AI → Integration Suite)
4 HTTP POST callback Doc AI sends callback to BTP Destination DOC_AI_ENRICHMENT_EXT — pointing directly to the Integration Suite iFlow endpoint.
recv iFlow triggered Integration Suite receives callback. Parses id + extractionResult. Begins AI Core enrichment calls.
⏳ Doc AI is now waiting HTTP connection held open. Processing paused until HTTP 200 is received back.
Phase 3 — Integration Suite calls SAP AI Core
5 Call RPT-1 deployment iFlow resolves XSUAA token, POSTs to AI Core inference endpoint for RPT-1. Sends vendor name + invoice fields.
→ RPT-1 inference Validates vendor ID, checks payment terms.
RPT-1
6 Receive RPT-1 result Vendor ID + payment terms stored in iFlow message context.
← HTTP 200 vendorId, paymentTerms, verified
7 Call Perplexity deployment iFlow POSTs to AI Core inference endpoint for Perplexity. Sends line items for GL account suggestion + confidence scoring.
→ Perplexity inference Enriches line items, returns GL accounts + confidence scores.
Perplexity
8 Receive Perplexity result GL accounts + confidence scores merged with RPT-1 data in iFlow message context.
← HTTP 200 enrichedItems, glAccounts, confidence
Phase 4 — Integration Suite responds to Doc AI
9 Build final response iFlow merges RPT-1 + Perplexity results into the Doc AI callback response format.
10 HTTP 200 received Doc AI receives enriched payload. Processing resumes.
← HTTP 200 {"status":"DONE", enrichedFields}
Phase 5 — Workflow Continues
11 Workflow resumes Enriched fields (vendor ID, payment terms, GL accounts) reflected in Workspace. Document status advances.
12 Status → Ready for Confirmation Validation workflow node complete. Document presented to reviewer in Workspace with all enriched fields pre-filled.
13 Human review (optional) Reviewer checks extracted + enriched fields in Workspace. Can correct field values or confidence-scored items before confirming.
14 Document Confirmed ✓ Reviewer confirms document (or automation confirms if confidence threshold met). Status → Confirmed. Document ready for downstream posting.

Key Technical Notes
🔐 Doc AI Auth & CSRF
  • BTP Destination DOC_AI_ENRICHMENT_EXT points directly to IS iFlow URL
  • Destination auth: OAuth2 Client Credentials or Basic
  • Target iFlow must support CSRF token validation
  • Destination name must be prefixed DOC_AI_
🔀 Integration Suite Role
  • Owns all AI Core API calls — single point of control
  • Resolves XSUAA tokens for AI Core independently
  • Can run RPT-1 + Perplexity in parallel (multicast step)
  • Merges both responses before returning to Doc AI
🏗 BTP Architecture
  • All components run on SAP BTP
  • AI Core endpoint: /v2/inference/deployments/{id}/predict
  • IS uses BTP Destination for AI Core connectivity
  • Extension triggers at: After Prediction or Validation status
SAP BTP Architecture  ·  Document AI sends the Extension callback via BTP Destination DOC_AI_ENRICHMENT_EXT directly to a SAP Integration Suite iFlow. The iFlow owns all AI Core communication — it resolves XSUAA credentials, calls RPT-1 and Perplexity deployments on SAP AI Core (sequentially or in parallel), merges the results, and returns HTTP 200 with enriched fields to Document AI. Doc AI resumes the workflow. No data leaves SAP BTP.
